## The Core Principles (P.O.U.R.)

**Perceivable: Can the user access and consume the information?**

The user needs to **see** or **hear** all content, regardless of how it's presented (e.g., text, images, video).

**Operable: Can the user successfully interact with and navigate the interface?**

The user needs to be able to **use** all controls (buttons, links, and forms) with whatever input method they prefer (e.g., keyboard, voice, or mouse).

**Understandable:** 
The user needs to **know what is happening** and **how to proceed**, ensuring the language is clear and the navigation is consistent.

**Robust:** 
The user needs the content to **work reliably** with their specific assistive technology (like a screen reader, magnifier, or older browser).

## **Focus management**

**Tab-based navigation:** We have by default many elements like anchor, input select, text area, etc., that are auto-focused, but in case we want to give a custom one, then we can use **tab-index.**

**Keyboard Shortcuts**: Like clicking N open a new post in Twitter, etc.

**Skip Links:** On focus there comes "skip to main content" to redirect the user to main content rather than nav links to be repeated again

**Tab trapping:** your focus should always be inside the modal if the modal is open.

We can achieve this by getting all the focusable elements, then the last focusable element, and then we can do modal. focus() when active element  == lastfocusable

**Page navigation:** Skip links can help, and then aria-live can announce what is changed for client-side rendered pages. currentElement.focus()

## Things to keep in mind in development to keep better accessibility.

1. Use the HTML semantics.
2. Add labels to form elements
3. Use contrast colors
4. write descriptive links
5. provide text for non-text content
6. Show where your focus is: The currently focused element is visibly highlighted
7. captions for video and audio
8. use wai-aria only if necessary
